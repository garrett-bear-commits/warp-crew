# Migrations

1. Add `packages/server/src/db/migrations/NNNN_<feature>_<what>.sql` (one tx per file; expand/contract; renames via views). Never rewrite an already-committed file. For a new CHECK, prefer `NOT VALID` then a follow-up `VALIDATE CONSTRAINT` in the next file, and mark each extra `-- foundation-n1-compatible-with-ordinal: N` as the first nonblank line (N = last ordinal of the prior image) only after a release that already ships this N-1 checker. Do not infer the parent from a `migrateUp` batch. `0014` → `0015` still takes `ACCESS EXCLUSIVE` for the CHECK scan; rehearse on a copy.
2. Locally: `pnpm db:up && DATABASE_URL=postgres://postgres:postgres@localhost:55432/foundation_dev pnpm migrate --up`, then `pnpm migrate --check schema.sql --write` and review the diff of `schema.sql`.
3. CI runs `pnpm test:pg` (migrations from empty on postgres:16).
4. Release: run `migrate --up` as the migrator role BEFORE starting the new image. This image's head is the 15-file `c94bf5d` head. It boots on `match`, or on `ahead` when extras are declared for **this** image's `expectedHead` (not a grandparent). Pending known files, checksum mismatches, skipped/duplicate ordinals, undeclared extras, and extras whose checksum/`result_head` drifted refuse. Isolated restore requires `match`. `migrate --up` refuses applied rows that are not a prefix of disk files. `migrate --status` prints `state`.
5. `--repair`: only after a reviewed, no-op edit to an already-applied file (comment fix). Re-records checksums and recomputes `schema_n1_compat` heads from each extra's stored parent ordinal in one transaction. If the extra file is on disk, it must still contain exactly one first-nonblank `-- foundation-n1-compatible-with-ordinal` matching that stored ordinal. Removing, changing, or newly adding a marker (no declaration row) refuses. Never use it to hide a real drift; write a new migration instead.
6. Rollback: N-1 means roll the **image** back and keep the new schema, and only after the rolled-back image already contains this checker. `c94bf5d` is exact-head and cannot boot against a later extra. Do not run `migrate --up` from the old image. Databases that applied unreleased rewritten `0015`/`0016` are rebuilt from empty.
