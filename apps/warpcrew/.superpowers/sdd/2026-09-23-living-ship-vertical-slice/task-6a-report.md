## Interface and behavior

- `startEncounter({ acceptanceId, encounterId, kind, seed, assignments, outputs })` returns a JSON-safe v1 state at revision/beat 0. Assignment data is cloned. Station outputs are snapshotted as numeric values; both a number and Task 5's `{ total }` shape are accepted, with an absent or invalid output defaulting to 100.
- `advanceEncounter(state, order = null)` leaves input untouched. Successful advances return `{ state, events }`; completed states return `{ state, events: [] }`. An unknown/out-of-window choice returns `{ ok: false, reason: 'order_unavailable', state }`; used, cooling-down, full-hull, and unaffordable choices report `used`, `cooldown`, `hull_full`, and `insufficient_resource` respectively. Rejections preserve revision, beat, and resources.
- Orders are `brace` and `repair`. Guided encounters allow one Brace use. Normal windows offer Brace or emergency repair; Brace has a three-beat cooldown and repair has a four-beat cooldown. Both costs and cooldowns are included in state/events; passing `null` takes no order.
- Every telegraphed window saves `orderOptions` metadata for each order in that encounter kind, including full shield cost, availability, current disabled reason, and remaining cooldown. `availableOrders` contains only currently usable actions; a null order always remains valid.
- Tell events include `target`, `system`, and `beatsToImpact`. Weapon damage, engineering repair, enemy impact, order, and terminal events name their target and amount where applicable. Seed and beat drive deterministic target variation; `eventIndex` remains saved but is deliberately excluded from target selection so order-emitted events cannot change the threat sequence. JSON round-trip preserves the next transition.
- Baseline output is 100. Each +10 Weapons output adds one damage per beat; each +10 Shields output improves incoming mitigation. Hits to weapons, shields, or engineering reduce that station's effective output until Engineering repairs the subsystem. Engineering repairs damaged hull over time, with higher output increasing repair amount, and restores one integrity point each beat while staffed. The tests exercise a later seeded system tell, reload the JSON snapshot, and compare the next transition. Guided victory comes from authored hull/damage and station effects. Normal zero-weapon combat can lose while preserving at least one hull and a loss reason; a functioning Weapons station can win. No economy, rewards, persistence, random API, or wall clock are involved.

## Task 6B integration notes
